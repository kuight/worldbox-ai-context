## 五、玩法内核（R2-9 后重写；旧版基于 0.7f 出兵线，已整节作废）
5.1 主轴 = 目标指派（D-017，未实现）。
    群友决定哪支军队压向哪里，这是"指挥"而非"作弊"。
    参考架构 = EmpireCraft：ActorExtension 的 FrontLineMoveTarget 方法族 +
    ConditionalWeakTable 自维护目标表 + AssetManager.tasks_actor 注册行为节点
    参与 AI 决策。[执行·实测 P-4B]
    已知失败路径，不要重走：ActorPatch.cs:149-152 的硬拦截守卫被作者注释。
5.2 节奏控制器 = pause / resume / set_speed（0.4.0 原生，最慢 slow_mo = 0.5x）。
    大战触发时切慢速，使 QQ 消息往返的数秒延迟不再致命——"大战微操"由此成立。
    仅认人工指令，bot 不自动改速度；检测到大规模交战时只发建议、等人点头。
    [执行·实测] 暂停态下桥接完全可用，不影响 /cmd 与播报。
5.3 打击类 = 天灾 / 战场变数，不是武器。
    依据：对平民致命、对军队近乎无效（3 发 lightning 打统帅格合计减员 1）。
    可用于 PvE 天灾场、制造变数、清理平民区，不承担主循环。
5.4 0.7f 出兵线 = 只读播报指标，不可操作（D-020，四条杠杆全部实测报废）。
5.5 硬性防呆两条：
    a) max_warriors == 0 时 isOkToSendArmy 恒为 true（浮点除零 = +Infinity），
       播报前必须单独判零，否则系统性说谎。
    b) 伤害延迟结算，回执必须两段式："已落地，结算中" → 5~10 秒后补发战果。
       立即采样必然报 0。
5.6 未决 / 未验证：spawn 增兵通路未验证；目标指派未实现；
    earthquake / tornado / atomic_bomb 的杀伤量级因 N 轮归因错误已重置为未知。

## 六、定价原则 [参谋·设计，依据 N 轮实测]
6.1 按目标收费，不按 power id 收费。
    依据：N 轮同坐标连续打击效果急剧递减（lightning 首发 -178，其后
    earthquake/tornado/atomic_bomb 在同片废墟仅 -2~-4）。杀伤量由目标人口密度
    与打击顺序决定，与 power id 几乎无关。按 id 定价会导致"便宜 meteorite
    砸满城是屠杀、贵核弹砸废墟是烟花"。
6.2 每座城市一个独立「被打击冷却」。首发全价，冷却期内对同城重复打击
    照收全价且明示"预期无效"。规则必须写在商品说明里，不能让玩家以为被坑。
    副作用（正收益）：天然抑制针对单人的车轮战。
6.3 power id 只决定"表现形式"与否决门槛，不决定价格档位。
6.4 建设类（墙 / living_house）按次收费 + 单人冷却，不吃城市冷却
    （目标不同，互不挤占）。
6.5 v1 阶段所有价格用行动点计（见八节），v2 换真实资源时只改扣款那一步，
    价目表结构不变。

## 七、初版商品清单（R3-V 后定稿：按目标形态分工）
7.1 野外点杀 —— lightning
    唯一实测能击杀军队统帅的手段（R2-9a 暂停态命中即杀，count_units 45→44）。
    ★ 对城市近乎无效：打 202 人城市精确中心 delta 仅 -4（R3-V-6）。
      根因是居民多在室内（暂停态 get_tile 显示 actor_count=0），点杀打空格子。
    定位：只对野外裸露单位有效。商品说明须直说"打城市没用"，避免玩家买错。
7.2 城市洗地 —— meteorite
    同一精确中心 1 发 delta = -180，城市 population 202→20（R3-V-6）。
    大范围 AOE 且摧毁建筑，室内居民一并清除。
    ★ 平衡警告：单发即可清空一座中型城市 → 最高价 + 最长城市冷却，
      必要时并入待批队列。这是目前唯一的战略级删除手段。
7.3 量级未知（上架但标注"效果未实测"）
    earthquake / tornado —— N 轮的 -2~-4 因延迟结算存疑，不作为依据。
    atomic_bomb —— 强制进待批队列（见 8.4）。
    ★ 定价锚点作废声明：N 轮"lightning 首发 -178"不再使用。
7.4 建设类（低价高频）
    墙 7 种全部 A 档且跨会话持久：wall_ancient / wall_evil / wall_green /
    wall_iron / wall_light / wall_order / wall_wild。
    功能等价、仅外观不同 → 同价，卖外观与投屏观赏性。
    living_house —— 目前唯一验证过的增兵通路（O 轮 actor_count 2→5）。
    ★ 目标文法只接「我国 / 我城」，不提供敌方目标位。
      理由：敌城盖房膨胀 attacker 槽位以钉住敌军的玩法不符合"模拟真实战斗"基调，
      不上架、不教学。机制客观存在但记为"扩展娱乐局候选"，默认锁定。[用户拍板]
7.5 排除（不上架）
    angle_tower / flame_tower / monolith / ice_tower —— 塔类 B 档，判定已闭合。
    clone_rain / equipment_rain —— P-4C B 档。
    spawn —— 未验证。
7.6 落点精度声明
    城市目标已精确：list_cities_ex 的 getTile().x/y 是 tile 网格坐标，
    与 invoke_power 同坐标系（R3-V-4 实测 16/16 指向城市区域，无海洋/空地误指）。
    ★ 旧聚类近似作废：实测偏差 0~56 格且无规律（R3-V-5）。
    本条仅对移动目标保留：打军队/统帅时从取坐标到落地之间世界会推进，
    非暂停态打偏概率真实存在，不赔。
7.7 城市不会被真正删除（设计红利）
    小城连挨 6 发 meteorite 从 16 人降到 2 人，is_alive 仍 true（R3-V-8）。
    洗地只是打残，城会长回来 → 玩法天然可重复，不会一晚清空地图。
    ★ 但 is_alive == false 从未观测到，bot 不得以此判断"城已毁"。

## 八、v1 / v2 路线与交互约定 [参谋·设计]
8.1 v1 目标不是好玩，是跑通链路：
    群消息 → 符号化目标解析 → 坐标 → POST /cmd → 回执 → 用户否决口子。
8.2 货币：v1 用时间当货币（每人按在线/挂机时长攒行动点）。
    原因：8724 目前只有 /health + list_armies，资源读写未落地。
    v2 资源命令落地后换真实资源扣款（D-015），改动仅限扣款那一步。
    [用户拍板] 经济最终用游戏真实资源，GM 不做平衡，抢好地区 = 发育好。
8.3 指令格式：只接受符号化目标，不开放裸坐标。
    形如「打 星辰国首都」「在 我城 造 wall_iron」「我国 造房」。
    「我国 / 我城」由 QQ 侧绑定表（QQ号 → kingdom_id）正向解析；
    反向校验（坐标 → 归属）不可行（get_tile 无 city_id/zone/kingdom），不做。
    输入摩擦本身即劝退骚扰，不靠技术校验拦。
8.4 否决机制（定稿）：贵指令（atomic_bomb、paint_tile、meteorite 视定价而定）
    进待批队列，God 在群里回一字放行或拒绝。
    ★ 时限 60 秒，超时默认拒绝并全额退款。
    ★ 不碰世界时间：否决期间世界照常跑，不自动 pause。
      理由：自动暂停会让任何人连发待批指令就能冻住世界；且否决权是初版脚手架，
      终局降格为普通玩家时一并拆除，不值得为它绑定世界时间控制。
    终局替代方案：atomic_bomb / paint_tile 改用"高价 + 长冷却 + 全群公示"兜底，无需人审。
8.5 并发与回执：≤5 人，桥接主线程串行 + 30 秒超时，无需排队系统。
    每条指令必回执：受理 / 扣款额 / 结果 / 失败原因。
8.6 静默失败必须显式反馈。已知会静默的情形：
    B 档 power（accepted 但无效果）、冷却期内重复打击、
    出兵线未达标。回执要区分"游戏拒绝"与"游戏接受但没效果"。
8.7 权限分级：God（用户，含否决权与撤销）/ FactionPlayer（群友）。
    ★ 硬约束：链路钉死 worldbox-mcp 0.4.0。0.5.0 起 FactionPlayer
    不能调 invoke_power（PERMISSION_DENIED），升级即砸掉整个玩法。
    同理游戏本体钉死 0.51.2，正式版已到 0.51.4，禁止升级。
