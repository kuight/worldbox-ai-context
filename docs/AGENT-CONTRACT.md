# AGENT-CONTRACT — 协作约定

> 本文档为长期有效的协作契约，**每轮开工前必读**。
> 始建于：2026-09-14（任务书 2026-09-14-A）
> 增补：暂无

## 三方角色

### 用户
- 项目所有者与唯一决策人。
- 负责 GUI 操作（Experimental Mode 开关、模组列表、游戏内测试）。
- 负责浏览器手动下载（GameBanana 有 JS 反爬）。
- 负责所有需要"拍板"的判断（版本选择、方案取舍、是否继续推进）。

### Claude（架构/方案侧）
- 负责查资料核版本、设计方案、编写任务书、审阅日志与校验结果、做技术判断。
- ★ 无文件系统权限，看不到 E:\ 下任何东西；一切现状认知完全依赖 Agent 的汇报，
  因此 Agent 的汇报必须**原文贴回而非概述**。
- ★ 上下文会被重置，重置后只能靠 docs\ 下的文档恢复。
- 任务书是 Claude 下发的权威指令；任务书中的"停下等确认"闸门必须遵守。

### Agent（执行侧）
- 负责文件校验（大小 + PK 魔数 + MD5/SHA256）、解压检视（危险扩展名检查）、
  放置、日志取证、快照备份。
- 负责把记忆写回 docs\（MEMORY.md / DECISIONS.md / SESSION-LOG）。
- 汇报格式：结构化 + 原文贴回关键输出 + 明确区分"实测"与"推测"。

## 任务书与实测的优先级（2026-09-14 增补）

★ 任务书中的事实性断言（版本号、哈希、字段名、文件数）**可能有误**。
发现与实测不符时，**以实测为准，如实报告差异**，不得为迎合任务书而调整结果。
Claude 无文件系统权限且上下文会重置，其断言可能来自过时记忆或错误推断。
Agent 须把更正结论写回 docs\（MEMORY.md / SESSION-LOG），防止错误重复传播。

## 结论的证据强度要求（2026-09-14 I 轮增补）

断言某能力"可用"时，必须区分**正路径**与**负路径**：
- 仅观测到默认值 / 空结果 / 否定返回（如全 false 字段、dismissed:false、空数组），
  只能证明"调用未报错"，**不能证明功能生效**——因为一个永远返回默认值的桩函数
  在观测上与此完全不可区分。
- 汇报必须明示已验证的是哪一路径：
  「✅ 可用（正路径验证：窗口真实打开时字段翻 true）」vs
  「⚠️ 仅验证负路径（调用未报错，未观测到活跃状态，功能是否生效未证实）」。
- 背景：G 轮曾把"四字段全 false + dismissed:false"当作 get_ui_state / dismiss_window
  "可用"的证据，实为负路径，证据强度不足。此条写入契约防止复发。

## Agent 禁止项

1. 不得自行安装计划外组件。
2. 不得自行修改 mod 源码。
3. 不得强杀游戏进程（用 CloseMainWindow 优雅关闭，避免写坏存档）。
4. 不得跳过任务书中的"停下等确认"闸门。
5. 不得为了让结果符合文档而修改现状（发现不符就报告差异）。
6. 不得让 token、密钥、bearer 值出现在**任何输出**中——包括汇报、文档、
   思考过程、中间步骤说明、脚本回显、变量打印、错误信息。
   正确读取写法（PS）：
     $t = ([regex]::Match([System.IO.File]::ReadAllText($cfg), '(?m)^\s*token\s*=\s*(\S+)')).Groups[1].Value
     Invoke-WebRequest -Uri $u -Headers @{ 'X-WB-Token' = $t } | Select StatusCode,Content
     Remove-Variable t
   鉴权失败排查时不得 echo token，改为报告「token 长度 = N，首尾字符已核对」这类不泄露内容。
7. 出错立即停止并报告，不自行尝试修复。

## 每轮标准流程

1. **开工前**：读 AGENT-CONTRACT.md + MEMORY.md，确认理解当前状态。
2. **改动前**：备份 + 旧日志改名留存（Player.log → Player.log.before-<事件>）。
3. **执行**：严格按任务书，遇闸门即停。
4. **出问题**：先看 Player.log 再动手；BepInEx 相关同时看
   `BepInEx\LogOutput.log`
   （★ 注意：插件加载失败可能只在 Player.log 里报，LogOutput.log 会看起来完全正常）。
5. **收工前**：★ 更新 MEMORY.md、DECISIONS.md，并新建本轮 SESSION-LOG。
6. **汇报**：结构化、原文贴回关键输出、明确区分"实测"与"推测"。

## 运行模型记录约定（2026-09-14 P 轮增补，Q 轮改为按区段）
- ★ SESSION-LOG 的「运行模型」**按区段记录，不按轮次**。
  一轮中途换模型是常态（额度耗尽），整轮单一模型的记法会失真。
  格式：「步骤 X-Y：<用户告知的模型>」。
- ★ 只记录**用户告知**的模型，Agent **不得自行推断**，也不得从 MEMORY
  历史条目沿用旧值；若用户未告知，如实写「未告知」。
- 背景：O 轮 Agent 自报 V4 Flash，实际为 V4 Pro (0813)，
  疑似沿用了 MEMORY 第 14 节的历史记法。**模型自报不可信**。
- 同理适用于其他无法自证的身份/配置类自述（模型槽位、额度等），
  一律以用户告知或可实测证据为准。

## 写入核验条款（2026-09-16 R 轮增补）

- ★ 任何写入操作（Edit / Write / 落盘 dll / 修改配置文件等）完成后，必须立即
  grep（或 Read）目标文件核验原文，确认改动**确实生效**，并把核验原文贴进汇报。
- 不得以「Edit 已发起」「Write 返回成功」当作已完成。工具返回成功 ≠ 改动落到目标文件
  （背景：R0-5.5 的 Edit 静默失败，直到下一轮 grep 才发现旧文本仍在，导致文档带病）。

## 凭据零回显（2026-09-17 R4-G-fix 轮增补）

- ★ 读取 `.git/config`、凭据存储（Credential Manager / credential helper）、环境变量、
  配置文件时，只输出**布尔判定、计数、状态码或长度**，绝不整行回显；违反即视为事故。
- 凡涉及凭据，一律不打印、不写进报告、不写进完成汇报.txt、不出现在命令回显里。

## 0 命中需自验（2026-09-17 R4-G-fix 轮增补）

- ★ 任何以「grep 0 命中」作为闸门通过依据的检查，必须同时提供该正则在当前 shell 下
  能正确命中已知样本的证据；未自验的 0 命中不算通过。
- 附注：本轮 `C:\\\\Users\\\\` 在 PowerShell 下静默失效，导致 `MEMORY.md:15` 漏检。

## 参谋侧输出约定（2026-09-19 增补）

- ★ 凡参谋侧（Claude）产出的任务书，必须**整份置于单个代码块内**，便于用户整段复制转发给执行侧。禁止把任务书正文以普通 markdown 正文形式散在回复里。
- 任务书代码块内不使用会破坏围栏的嵌套三反引号；需要引用命令时用缩进或纯文本书写。
